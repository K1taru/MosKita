5. Procedures

### 5.1 Procedure Overview
The project was executed in an end-to-end workflow from data preparation to model export. The steps below document the exact process used for the final 70-epoch model.

### 5.2 Step-by-Step Procedure
1. Define project class schema.
    The final schema used in training is: discarded_tire, flower_pot, coconut_shell, basin, drain_inlet, drum, bucket, styrofoam_container.

2. Prepare and validate annotated datasets.
    Multiple annotation sources were normalized and merged into the project format. Class remapping and split organization were verified before training.

3. Assemble train/validation/test directories.
    Final assembled dataset path used by training:
    data/annotated/data.yaml

4. Configure training run parameters.
    Key settings included epochs=70, imgsz=640, batch=24, optimizer=AdamW, lr0=0.001, lrf=0.01, weight_decay=0.0005, and deterministic seed=42.

5. Launch model training in notebook workflow.
    Training was executed through the project training notebook and saved under run name moskita_v1210.

6. Select the final checkpoint.
    The best-performing checkpoint from the 70-epoch run was used:
    models/runs/moskita_v1210/weights/best.pt

7. Evaluate performance on validation and held-out test sets.
    The selected checkpoint was re-evaluated on split=val and split=test to report final precision, recall, mAP@50, and mAP@50-95.

8. Export deployment artifact.
    The final model was exported to ONNX and stored in:
    models/exports/moskita_moskita-v12_yolo26n_img640_ep70.onnx
    and alias:
    models/exports/moskita.onnx

9. Perform result interpretation.
    Training curves, confusion matrices, and class-wise test metrics were analyzed to identify strengths, limitations, and class imbalance effects.

10. Produce technical documentation and submission bundle.
     Findings, methods, and artifacts were compiled into this report with IEEE-style structure and APA references.

### 5.3 Reproducibility Controls Applied
1. Fixed random seed: 42
2. Deterministic mode: enabled
3. Complete run artifact retention: args.yaml, results.csv, weights, curves
4. Explicit model export naming with epoch count in filename
