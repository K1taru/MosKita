8. Conclusion:

### 8.1 Conclusion
This project successfully developed and documented an end-to-end dengue breeding-site object detection workflow using the MosKita repository. The final selected model, trained for 70 epochs (run moskita_v1210), achieved:
1. Validation: mAP@50 = 0.9102, mAP@50-95 = 0.7861
2. Held-out test: mAP@50 = 0.9340, mAP@50-95 = 0.7985

These results satisfy the technical objective of producing a high-performing detector under the current 8-class schema and demonstrate reproducible training-to-export execution.

### 8.2 Key Learning Points
1. Object detection offers stronger field usefulness than image-level classification because it localizes potential breeding containers directly.
2. Aggregate metrics can hide minority-class weakness; class-wise analysis is mandatory for safety-critical and public-health use cases.
3. Reproducibility practices (fixed seed, deterministic setup, full run artifacts) improve report reliability and future model iteration.
4. Export readiness (ONNX artifacts with verified file integrity) is essential for bridging research and deployment.

### 8.3 Limitations
1. Class imbalance remains significant, with minority classes requiring more data.
2. Very small test supports for selected classes reduce statistical confidence in those per-class scores.
3. Real-world edge benchmarks on Raspberry Pi 5 are not yet fully quantified in this report and should be addressed in deployment validation.

### 8.4 Recommended Next Steps
1. Increase training and test support for basin and styrofoam_container classes.
2. Add deployment-focused benchmarks on Raspberry Pi 5 (latency, thermal behavior, sustained FPS).
3. Expand hard-case dataset collection for clutter, partial occlusion, and low-light scenes.
4. Add calibration and confidence-threshold tuning for operational alerting quality.
